# MarketAski

Telegram-бот, который помогает вести канал: составляет контент-план, пишет тексты постов через LLM, даёт их отредактировать и публикует в канал сразу или по расписанию.

Стек: Python 3.12, aiogram 3, SQLAlchemy 2 (async) + PostgreSQL, Redis для состояний диалога, любой OpenAI-совместимый API.

## Что умеет

**Анкета.** При первом `/start` бот спрашивает нишу, описание автора, цель контента и просит привязать канал. Канал привязывается пересланным из него сообщением или по `@username`. Бот должен быть администратором канала с правом публикации, а пользователь — администратором этого же канала.

**Контент-план.** Пользователь выбирает цель (продажи, вовлечение, экспертность, личный бренд или своя тема) и количество постов: 5, 7, 10, 14 или 30. Модель возвращает список тем, бот сохраняет их как посты плана. Старые планы лежат в «Истории планов» в профиле.

**Редактор поста.** Текст поста генерируется при первом открытии. Дальше его можно:

- переписать целиком;
- поправить через модель короткой инструкцией («короче», «добавь призыв»);
- заменить своим текстом, форматирование Telegram сохраняется;
- сменить тему с тезисами, текст будет написан заново;
- дополнить одним фото или видео. Если текст длиннее 1024 символов, бот предложит сжать его под подпись.

**Публикация.** Из предпросмотра пост можно отправить в канал сразу, запланировать на дату (`ДД.ММ.ГГГГ ЧЧ:ММ`) или расставить весь план по графику: `Пн Ср Пт 10:00`, `Каждый день 18:30`. График начинается с завтрашнего дня.

Если отложенный пост не вышел (нет доступа к каналу, Telegram отклонил текст, бот был выключен дольше допустимого), он получает статус «не опубликован», а автору приходит сообщение с причиной.

### Команды и меню

| Что | Действие |
| --- | --- |
| `/start` | Анкета для нового пользователя, главное меню для знакомого. Сбрасывает незавершённый ввод |
| `/plan`, «Мой контент-план» | Последний план со списком постов |
| «Профиль» | Просмотр и правка ниши, описания, цели, канала; история планов |
| «Создать новый план» | Выбор цели и количества постов, генерация |

Бот отвечает только в личных чатах.

## Запуск

Нужны Python 3.12, PostgreSQL и Redis.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # и заполнить значения
python main.py
```

База и пользователь PostgreSQL:

```bash
createuser marketaski --pwprompt
createdb marketaski --owner marketaski
```

Таблицы создаются при старте. Redis достаточно запустить с настройками по умолчанию.

Бот работает через long polling, внешний адрес не нужен.

## Переменные окружения

Все переменные с пояснениями есть в `.env.example`.

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `BOT_TOKEN` | да | | Токен от @BotFather |
| `OPENAI_API_KEY` | да | | Ключ API модели |
| `OPENAI_BASE_URL` | да | | Адрес OpenAI-совместимого API |
| `OPENAI_MODEL` | | `gpt-5-mini` | Модель |
| `OPENAI_TEMPERATURE` | | `0.75` | Температура. Пустое значение — параметр не отправляется |
| `OPENAI_TIMEOUT` | | `60` | Таймаут запроса, секунды |
| `OPENAI_MAX_RETRIES` | | `2` | Повторы при сетевой ошибке, 429 и 5xx |
| `DB_USER`, `DB_PASS`, `DB_NAME` | да | | Доступ к PostgreSQL |
| `DB_HOST`, `DB_PORT` | | `localhost`, `5432` | Адрес PostgreSQL |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB` | | `localhost`, `6379`, `0` | Адрес Redis |
| `REDIS_PASSWORD` | | пусто | Пароль Redis |
| `TIMEZONE` | | `Europe/Moscow` | Пояс, в котором пользователи вводят время публикаций |
| `SCHEDULER_POLL_INTERVAL` | | `30` | Период проверки отложенных постов, секунды |

Часть моделей (например, семейство gpt-5 у OpenAI) принимает только температуру по умолчанию. Для них `OPENAI_TEMPERATURE` нужно оставить пустой, иначе API вернёт ошибку 400.

## Как устроено

- **Расписание хранится в таблице `posts`** (статус `scheduled` и время). Планировщик раз в `SCHEDULER_POLL_INTERVAL` секунд выбирает посты, время которых наступило, и публикует их. Перезапуск бота расписание не теряет. Строка поста блокируется на время отправки.
- **Время публикаций** хранится без часового пояса и трактуется в поясе `TIMEZONE`.
- **Проверка владельца.** ID поста и плана приходят из callback-данных, поэтому перед любым действием бот сверяет владельца.
- **Ошибки модели не попадают в посты.** При сбое или пустом ответе прежний текст остаётся, пользователь видит сообщение об ошибке.
- **HTML.** Ответ модели проходит очистку: остаются теги, которые понимает Telegram, незакрытые закрываются, `<` и `&` в тексте экранируются. Та же очистка выполняется перед отправкой в канал.
- **Промпты.** Данные пользователя вставляются между маркерами `<<<` и `>>>`, системный промпт требует считать их материалом, а сами маркеры из ввода вырезаются. Длина каждого поля ограничена.
- **Очередь на пользователя.** Апдейты одного пользователя обрабатываются по одному, двойное нажатие не запускает две генерации.
- **Логи.** Тексты пользователей, промпты, токены и параметры SQL-запросов в логи не пишутся.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
ruff check .
```

Тесты не ходят в сеть. Модель и Telegram подставные, база — SQLite в памяти. Сценарии в `tests/test_flows.py` пропускают апдейты через настоящий диспетчер aiogram.

## Что не доделано

- Миграций нет. Таблицы создаются через `create_all`, при изменении моделей существующую базу нужно править вручную.
- Отложенную публикацию нельзя отменить кнопкой, можно только назначить другое время.
- Прикреплённое медиа нельзя убрать отдельной кнопкой. Альбомы не поддерживаются.
- «График плана» ставит в расписание только посты с готовым текстом. Текст появляется при первом открытии поста, поэтому перед запуском графика посты нужно открыть.
- Темы постов меняются только вручную, подбора темы моделью нет.
- Нет ограничения на число генераций для одного пользователя.
- Очередь апдейтов держится в памяти процесса. Для запуска нескольких экземпляров её нужно заменить на `RedisEventIsolation`.
- Дата в «Истории планов» показывается по UTC.
- С настоящими PostgreSQL, Redis и Telegram текущая версия не запускалась: проверена только тестами. Перед выкладкой стоит пройти сценарии на тестовом боте.

## Обновление со старой версии

- Прежний `.env` подходит, новые переменные необязательны.
- Раньше время публикаций считалось по часам сервера. Теперь оно берётся из `TIMEZONE`.
- Таблица `apscheduler_jobs` больше не используется, её можно удалить. Посты со статусом `scheduled` планировщик подхватит из таблицы `posts`.
- Кнопки под старыми сообщениями перестанут работать: формат callback-данных изменился. Бот ответит «Кнопка устарела».
- Индексы на уже существующих таблицах нужно создать вручную:

```sql
CREATE INDEX IF NOT EXISTS ix_posts_plan_id ON posts (plan_id);
CREATE INDEX IF NOT EXISTS ix_posts_user_id ON posts (user_id);
CREATE INDEX IF NOT EXISTS ix_content_plans_user_id ON content_plans (user_id);
```
